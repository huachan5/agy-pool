# agy-pool M4｜完整测试用例清单

**版本：2026-11-28 · 执行清单，非测试报告。** 范围以 [M4 PRD v1.1](agy-pool-M4-PRD.md) 的 FR-01～09 / AC-01～07 为准，纳入 [M4 技术方案](agy-pool-M4-技术方案.md) §8（F01～F13 / R01～R07）和旧版本仍有效的注册、脱敏、并发及迁移回归。Otty 操作与证据分级见 §1、§4。HTML 原型、模拟菜单、探针与正式验收分开计。

## 0. 怎么执行与记录

- **层级**：`F`＝合成事件、假 AGY、隔离 SQLite、故障注入；不使用真实账号或真实任务库。`R`＝两个平台各在实际终端/AGY/HUD/Pool 版本上单独执行。`S`＝能力探针，不能替代 `R`。用例组标题给出原 FR/AC 对应，行号是可独立复测的 Case ID。
- **初始状态**：`F`、`R` 下的用例均为**待执行**；表 1 单独记录已有实测。结果用 `通过 / 未通过 / 阻塞 / 未执行`，有子场景未测就单独挂起，不能把另一平台结果填过来。
- **测试数据**：空白测试目录；合成槽位 `main`、`backup`，且账号摘要不同；同目录双分屏 L/R，另备查询分屏 Q；新库和 v0/v1 数据库副本；合成日志、一次性无敏感标记 `M4-HANDOFF-<run>`。分别记录 `launch_id`、`conversation_id`、任务 TID、棒次、意图、attempt、包摘要，按本地需要脱敏，不记录凭据、完整聊天或无关页面。
- **真机权限**：先准备空白测试目录。信任目录不等于获准发送测试首问、真实登录／切号、干扰共享登录域或修改全局配置。此类用例须先有专用账号、隔离场地和明确授权；默认不碰现用分屏，不自动操作浏览器或输入凭据。正式 M4 未有可运行实现时不硬跑 `R`；夹具失败不继续有后果的真机步骤。
- **记录模板**：`Case ID | 测试层级 | 平台/OS/AGY/HUD/Pool 版本 | 前置条件 | 实际结果 | 脱敏证据 | 状态`。对负例至少对照意图数、`agy -i` 调用数、下一棒数及交付次数；对只读查询对照 DB 与工件状态。

## 11. 执行顺序与签收

1. **当前只做技术可行性调研**：暂停菜单、分屏、退出等功能用例的执行。S01–S06 仅作能力证据；S06 已补足 Otty 单分屏透明代理下的实际键序列，分片及菜单集成留待开发后，不计 AC 通过。
2. **M4 实现就绪后并行**：跑所有 `F`，同时安排无需共享登录变更的 `R`。含真实首问的 `R` 单独确认；不用真实配额触边界，边界值用夹具。
3. **最终发布**：两平台分别补齐 AC-01～07 的 `R`，含目标账号真实绑定和 `-i` 实际读包、往返、异常/并发阻断；任何信号缺失标未通过/阻塞。若只有降级或仅单平台可用，回产品作范围评审，不自动改成发布通过。
