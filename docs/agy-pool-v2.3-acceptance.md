# agy-pool v2.3 补充验收用例（M1 / M2）

这是 v2.3 的增量用例。旧版 `agy-pool-test-cases.md` / `.csv` 仍仅供业务场景参考；本表以 SQLite 和现有 HUD 为准。不在自动化测试中操作真实 Google 登录。

| 编号 / 追溯 | 前置条件与数据 | 操作 | 可观测预期 |
|---|---|---|---|
| V23-01 / AC-06、AC-07 | Windows，同一名用户登录；两个独立 `AGY_POOL_DB`，都创建 `T1-seg1`；日志分别含 `ONLY_A` 与 `ONLY_B` | 分别生成交接包 | A 包含 `ONLY_A`，不含 `ONLY_B`；B 反之；两套锚点、交接包与段探针物理路径不同。 |
| V23-02 / AC-07、AC-14 | 同一个 Windows 登录会话，A、B 指向不同的库；A 处于人工换号等待 | B 执行 `switch --force` | B 退出码 `3`，没有出现登录引导；`--force` 不能绕过换号锁。随后 A 退出，B 可以重新获取锁。 |
| V23-03 / AC-08、AC-09 | A 的源段 `main` 已退出，交接包已冻结；在浏览器已经改登 `backup` | `switch T1 --cancel`（无 `--to`） | 退出码 `0`，源段回到 `closed`，交接包原样保留；不执行登出或改登操作；提示本地回滚不改变 Google 登录态。 |
| V23-04 / AC-02、AC-08 | 同 V23-03，实际登录仍为 `backup` | `start "另一个任务" --account main` | 退出码 `4`；不新建线程，不拉起托管工作会话。 |
| V23-05 / AC-08、AC-11 | 专用账号探针分别使用：目标账号的新记录、其他账号的新记录、缺失、坏 JSON、空邮箱、过期记录；同时共享文件写入目标账号 | 对每个输入执行校验 | 独立新记录匹配退出码 `0`；错号 `4`；其余 `1`。失败不拉起下一棒、不读共享文件。正常结束和失败退出均清理专用账号探针。 |
| V23-06 / AC-05、AC-08（M4 真机） | 已启用现有 HUD；源段退出并冻结；仅使用用户自己授权的两个账号 | 分别演练：切对号、切错号、重新登录后状态不刷新就退出 | 真实日志可定位且切对能接棒；错号及状态未刷新不接棒，不以登录引导窗口的时间戳代替重新登录后的账号验证。 |
| V23-07 / AC-09、AC-13 | 源段仍运行；另一组数据源段已退出但同一 Windows 登录会话内换号锁被占用 | 分别执行 `switch --force`、`start` | 第一项返回 `6`，不得进入登录引导；第二项返回 `3`，不启动会话。 |
| V23-08 / AC-06、AC-11、AC-12 | 锚点包含模拟密钥；另备合规但恰好 600 估算 Tokens 的锚点和超大 `task.md`/日志 | 分别保存锚点、生成交接包 | 拒绝含密钥的锚点，不覆盖原文件；合法锚点全文保留，超大交接包仍 ≤ 3,500 估算 Tokens。 |
| V23-09 / AC-09 | 冻结后第一次启动下一棒在 3 秒内退出 | 尝试覆盖预览或改锚点；然后重试同一切号 | 未取消前改写返回 `2`，原包字节不变；失败尝试可审计；一次成功只新增一棒，不跳号或重复启动。显式 `--cancel` 后可重新编辑锚点与生成交接包。 |

M2 的 Windows 跨库互斥指同一 Windows 登录会话内的终端；不宣称防止非托管窗口直接发起人工换号。M3 HUD 徽章和 8% 提醒另验，`resume` 留到 Phase 2。
