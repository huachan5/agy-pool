## 2. 两仓职责与取舍

- **`agy-pool` 是决策与状态的唯一 M4 写者。** 预配置 `agy` 入口调用托管前台控制器，使用独立解析出的原生可执行文件，防止包装递归；参数、终端、退出码默认透传。它拥有启动实例、账号注册/核验、进程冲突与锁、SQLite、包、菜单确认及恢复。预配置未齐、非交互不支持、普通参数不兼容或没有可用事件时保持原生行为，不替用户新开任务。子进程没有其他待接棒包的授权环境。托管的 shell/terminal 不把 cwd、pane 或账号当任务键。
- **`agy-hud` 只作观测和渲染。** 从实际新帧采集最小可校验证据并发布到专属通道，读取 Pool 公布的短视图、画徽标/提示；没有权限创建任务、切号、领取包、捕获全局按键。M4 模式禁止旧 `sync_pool_live_telemetry()` 和旧行动提示；M3 模式兼容既有环境。两平台保持标准库、短超时、HUD I/O 失败不阻塞 `agy`，不在渲染热路新增子进程，留用旧 P95 新增 ≤5 ms 预算。
- **推荐控制器 + 版本化本地事件**：将原生/平台能力集中在适配层。拒绝以 HUD 直接 SQL 控制工作流（无法绑定前台/退出，且旧 HUD 可重写 M3 遥测）；拒绝以 cwd/最近改动/账号扫盘自动认领（无法满足双分屏与显式意图）。保留已支持的本地标准库和 SQLite，不引入常驻服务或网络协同作为前置。
- **顺序**：原生启动（每次独立 `launch_id`）→ 真实 ID + 已提交首问唯一登记（账号可待归属）→ 核验本棒账号与控制权后才显示操作入口 → 用户明确菜单确认并证实安全退出（前台先选，降级先退） → 共享域门禁 → 冻结包 → 手工官方登录及新鲜核验 → 检查目标 5h/再次扫冲突 → 绑定且仅授权一次同窗 `-i` → 收到可归属的真实新 ID 事务推进。登录前的安全阻断与冻结可分开：有冲突可先保留已冻结包，但不能进入会改变登录的步骤。

## 3. 证据来源与版本化通道

### 3.1 上游证据和门禁

| 信号 | 已知来源 / 候选 | M4 接受条件，以及不接受的替代物 |
|---|---|---|
| 真实对话 ID | HUD stdin `conversation_id` 或 `session_id`；旧旁路 `session_id` 合并了两者；AGY 本地对应的 CLI brain 会话目录 | 只认探针验证为**实际聊天 ID**的字段；已验证启动实例/事件生产方、ID 非空且满足白名单，帧与 canonical 日志归同一对话。字段冲突或只出现临时 UI/进程 ID 时停。唯一键 `conversation_key=(native_namespace,native_id)`；命名域须在账号和分屏间稳定，真机确认前不按账号/cwd 拼键掩盖冲突。 |
| 首条真实用户消息 | 候选：原生命令提交事件，或同一 ID 的 `brain/<id>/.system_generated/logs/transcript.jsonl` 中已完整写入、去重后 `USER_EXPLICIT/USER_INPUT/DONE`（旧方案 §5.5） | 以首个**已实际提交到对话**的用户 query 为准，需验证语义、ID 绑定和完整性。不要求模型成功回应。过滤 `/exit`、审批、仅输入未发送、系统/工具、空 init、接棒 `-i`、登录探针；只有历史尾片且不知首问时不首登。首问事件迟到可等并重试取证，不靠渲染时间；恢复已绑定的 ID 可以查找既有任务，不重建。 |
| 原生标题 | R4 候选 stdin `conversation_title`/`session_name`/`title`；日志有 `CUSTOM_TITLE`、`SESSION_TITLE`、`TITLE_UPDATE` 等候选 | 只启用实测证明属于原生会话名称的字段/事件，不含自己生成的摘要、第一句、占位标题或 `model` 标签；证据须指向 `seq=1` 的 ID，允许原始首棒标题晚到并从 `todo` 一次填充，更新不据后来棒。移除终端控制字符及凭据；可安全存下的完整标题在查询展示，HUD 单独截断。 |
| 当前账号身份 | AGY 实际的已登录身份观察；旧 HUD 从 `email` 生成摘要，M3 登记可复用格式 | 启动器传的 `main`/`backup`、`active_machine_account`、共享缓存/共享探针不能证明身份。适配器从已验证的原生身份来源读取，内存规范化，M4 通道只出脱敏提示/摘要；预配置托管入口的正常启动已有真实 ID + 已提交首问时，账号身份缺失不阻挡登记。首棒记“未核验/待归属”，不猜槽位、不显示换号入口、不判断该任务低额、不生成或发送交接包；同棒可信身份晚到时补归属。账号修改/撤销须使旧证据失效。 |
| 配额和重置窗口 | 已有 `quota["gemini-5h"]`（fraction 或 percentage；`reset_time`/`resets_at` 或 `reset_in_seconds`）、`gemini-7d`、`3p-*` 解析；旧背景缓存和 M3 DB 只作显示参考 | 5h 模型行为只用**同一身份与同一上游采样**的 Gemini 5h；记录来源 `sampled_at` 而非渲染/读取时刻。数值有限且范围正确，按未四舍五入的百分数 `≤5.0`；验证 legacy `argon` 确系同池才作为候选兼容。以服务端稳定窗口 ID 或可独立验证的绝对 reset 为键；相对倒计时仅在有真实采样基准并验证稳定性后可换算，不按每次重绘合成窗口。 |
| 重登后新鲜身份 | 旧实现有专用 `AGY_STATUS_STATE`；新方案优先官方新鲜身份信号，其次是同窗、无任务内容的受控交互校验会话 | 在官方引导退出或明确完成后新开探针：新 nonce、独立输出、探针启动身份、真实上游身份采样在 challenge 之后，命中目标注册摘要；新鲜观测必须非缓存/非前置 guide，且有可验证 auth generation 或等价的持续登录绑定。文件 mtime、网页成功提示、HUD `timestamp=time.time()`、无来源的环境账号、前一轮探针都不算。 |
| 安全退出与实际交付 | 平台子进程 wait/PID 检查、原有 `agy -i` 启动模板 | 正常安全退出：用户 `/exit` 后有对应子进程/终端的正常结束信号；忙碌、崩溃、权限错误或没等到信号不等于安全退出。实际交付：由本 attempt 的新对话/身份证据先确认 `new_id` 归属，再独立以匹配包的实际读取证据验证 `-i`，不把模型口头复述或退出码当读取凭证。 |

**证据时效（数值等可信探针结果后再定）**：

- **实时 5h**：区分 `source_observed_at` 和传输 `received_at`，以真实采样时刻和未跨 reset 为准，旧展示缓存不视为 M4 新鲜行为读数。仅 7d 更新不刷新 5h；缺失/过期/超前/错号归未知，不按 0%。窗口不可可靠识别但确认新鲜且 ≤5%，只持续显示低额，不发一次性提醒；同窗口不重发、下一窗口可再提醒后，FR-03/AC-02 才完整通过。
- **授权时的新鲜认证**：须晚于本次 challenge、登录未变且在单调计时的有效窗内，贯穿授予和实际调用 `-i` 之前的门禁。超时、重启或 epoch 变化须重新核验；任何历史证据不延长这个有效窗。
- **历史新对话证据**：确认新 ID 在本次已授权 attempt 的实际启动后产生，证据须绑定同一启动实例、原分屏及该会话产生时的实际目标身份；迟到/重放可用于幂等对账或补登记，不按当前认证 TTL 抛弃。按来源、因果关系及授权记录校验，不把旧查询、相近时间或文件 mtime 当证明。该证据永远不能授权 `-i`、再次投递，或恢复一个已失去的分屏控制权。

**归属核验后的竞态是单独门槛。** 平台全局锁只能约束采用协议的入口，三次进程清单也不能锁住用户另开原生 `agy` 或外部共享登录切换。要在 `-i` 开启前证明真正消费初始提示的客户端会固定在目标身份上（可验证的官方 profile/认证上下文绑定，或原生可检查的认证代次与交付原子门禁）；不因猜测隔离而创造账号沙箱，不用第二次扫描充当此证明。如果官方入口只读全局可变会话、无法确认实际消费身份，则该平台保持待接棒、禁交付；不能先发 `-i` 再靠错号帧“补救”。

- M4 子进程继承**仅本次**暴露的私有邮箱目录或本地 IPC 标识。配对控制器预先分配启动 ID、用途（普通、官方校验、接棒）和一次性关联值；事件还须匹配由控制器记录的生产方/进程与终端所有权。环境中的 `attempt_id` 只关联，不证明身份、交付或权限。`probe_id` 与 `launch_id` 作用域隔离；普通启动没有路径、挑战或接棒授权。无协议或版本不识别即保留原生 HUD/AGY，不回落到宽松的 M4 识别。
- HUD 投递白名单字段：版本、事件类型、生产方范围/序号、原生来源和少量数据。不传正文、真实邮箱、凭据或全量帧；首问正文只在合法日志范围内按需读入内存，经过脱敏、限额后才可写锚点（不入 DB）。事件序号用于重放/传输去重，不等同于日志 `step_index`；先验检查范围、来源、类型和进程，再幂等应用。同一事件重复即复用结果；同一序号异载荷、同一 attempt 两个不同新 ID 进入待核对，不自动改归属。
- 初版可用每实例私有邮箱：关键事件独立文件、原子发布、控制器事务后 ACK；重复渲染不追加，采样类仅保留较新观测，首问、标题、认证和新 ID 不被心跳覆盖。限制单帧/队列大小，队列满或 IO 忙时 HUD 不阻塞，关键事件重取或保持未知而非伪造。M4 的视图亦原子发布且绑定 `launch_id` 与当前真实 ID；未绑定、错号、老实例或坏视图降级为原生渲染。实际目录和后台轮询预算在两分支联调测量。

## 4. 持久化与数据字典

表名为拟议契约，不是现有 schema。**必**＝记录必需；**条件**＝仅证据或指定阶段出现后必需；**可**＝允许为空。统一 UTC（持久化）、单调时钟（同次进程短 TTL）；PID 与创建时间成对，`boot_id` 确实可用才用于解释重启，不能从时钟猜测。任何持久化路径都在用户私有目录，按默认 `pool.db` 与自定义库分区；平台分别校验目录权限、ACL、符号链接/重解析点，不跟随未经验证的路径。

| `delivery_receipts`：`attempt_id`,`segment_id`,`packet_digest`,`delivery_state`,`read_ref`,`observed_at` | 按归属的新会话和实际包读取证据；attempt/棒/包摘要与状态必，读事件引用和时间在 `delivered` 时必 | 每 attempt 最多一个收据；`read_ref` 只存核对用事件定位与结果，不存读取正文。无证据留 `delivery_unverified`，不影响新 ID 已提交，也不产生第二次启棒权。 |

**文件保护**：用现有 `guard/redact` 加首问/标题的控制字符、结构字段、路径白名单和最终输出守卫。引导指令只含固定文案与安全路径，不把锚点/完整日志传入命令行；拒绝换行、控制字符、含秘密或超长路径。自动日志来源限制在已验证原生根和本 ID；命令显式 `--transcript` 走人工兼容路径，不当作自动绑定证明。macOS 默认目录 `0700`、文件 `0600`；Windows 需验证当前用户限定的 DACL、重解析点拒绝和目录继承规则。M4 不主动读取官方凭据文件；保留的 M3 探针格式仅限旧链独立兼容，不允许 M4 悄然写明文邮箱。

### 4.1 SQLite 迁移、共存、回退

1. **兼容策略**：沿用单库 WAL、外键、短 `BEGIN IMMEDIATE`、既有 TID/棒次/槽位/锚点/命令 JSON 字段，不用新 JSON 状态库。建议 `meta.schema_version=2` 保留旧表列并增量迁移；旧 Pool 只接受 `0/1`，禁止 v1/v2 Pool 并写。在同一台机实际可能共享登录的所有 Pool 库共用运行时门禁；自定义 DB 只隔离文件和任务，不隔离真实账号。
2. **升级**：先只读盘点 version、表/列、现有 ID 重复/不合法、活动会话、启动中/被冻结的换号；退出工作进程并暂停旧写者后，以 SQLite backup API 生成私有迁移前快照，记录校验结果和受管工件清单，不能只拷贝 WAL 模式主文件。v0 先走现有 v0→v1，v1→v2 迁移增加所需表/列，并在受控迁移事务内按 SQLite 表重建流程复制 `segments`、重建索引及验证外键；只对 M4 首棒 `unverified` 放开 `account_id` 的非空约束，其余保留为条件 CHECK。跑完整性和外键检查后最后提交 schema 版本；不为配合旧 `NOT NULL` 挂 `main`/`backup` 或新增假账号。若表重建或上下游兼容不能满足，列为 FR-01 技术缺口，可评估独立 M4 首棒表叠加查询（代价是双结构归属/迁移），不能退回“身份已核验才登记”；空库仅显式 `init` 或明确托管启用创建，未知版本拒绝。只回填无冲突的可靠旧 ID，其余保留历史可查并标“不可信归属”，禁止据此自动生新任务/领包或改写旧数据；历史 `(thread_id,seq)` 重复保持原状并隔离，唯一约束先覆盖新增 M4。旧冻结包没有 M4 意图，不自动获得授权；需人工核查或旧流程收尾。
3. **协议共存**：旧 HUD 有能力在新库写旧列，仅加列并不能阻止它。新 wrapper 不向不支持 M4 的 HUD 注入 M3 段变量；M4 启用前核对 HUD 能力并确认已停旧写者，启动时未握手则原生/无 M4。M4 读新的 5h/ID/auth 记录，不信旧回写；独立手工链仍走旧合同。不要用假版本强行让旧 Pool 写 v2。
4. **只读查询**：`list` / `status T1 --json` 单次 `mode=ro`、`query_only` 的兼容投影，禁 `init_db`、迁移、`reconcile`、进程扫描、副作用与删探针；必要时展示“最后记录/待核对”。旧记录的键和值类型不变；M4 待归属首棒的 `current_segment.account_id` 为 JSON `null`，加 `account_binding_state=unverified`，文本显示“账号待归属”，不伪造账号。另加 `handoff_state`、`pending_intent`（目标、阻断原因、包是否可用）、`delivery_state`，不返回包内容/认证引用。无库或 WAL 读条件不足时给出只读提示，不为查询新建库、目录或修复旁文件；不对仍在写的 WAL 库用 `immutable=1` 忽略有效记录。由控制器退出回调和显式恢复更新状态，不由查询修状态。
5. **回退**：首选停用 M4 wrapper/HUD 行为，保留 v2 DB/包可查而不切登录。若必须降回 v1，先停 v2 写者、记录/导出 v2 增量及私有工件、备份当前状态，再用校验过的 v1 快照恢复到独立目录/路径并重新校验；不就地把版本改成 1，不自动恢复实际官方登录。停用/回退不丢弃未决 attempt 和证据，不允许旧人工路径绕开共享登录阻断；重启回 v2 前先排查该 attempt，不自动补跑。回退后 v1 快照不含升级后的 M4 任务，用户须知可在归档 v2 查询。

## 5. 状态、并发与崩溃恢复

### 5.1 常规登记、提醒和菜单

- 预配置托管入口的普通启动先记临时上下文；收到同一真实 ID 和已提交的首问即事务分配 TID、认领 `conversation_key`、写 #1、事件与当前指针，不等账号。缺失身份时提交可查的 `unverified` 棒；可信身份晚到，仅按原生产方、ID、同一棒 CAS 补槽位，绝不另建。身份始终不来仍保留该棒，不归属配额、不提醒、不显示切号入口、不读/冻结/发送换号包。重复、乱序、恢复同 ID 都复用同一记录。发起切换另外校验当前账号、原分屏独占控制权和正确源棒；同一对话同时附着多分屏、错号或无控制权只读展示。不同 ID 独立，cwd 只关联工作目录。
- 在新鲜、当前账号已归属的 `gemini_5h ≤5.0%` 上做低额状态；窗口可靠才事务去重。低额不创建意图、不退出、不登录。M4 HUD 只有一个换号提示源，旧 8%/按色动作停用；7d/3P 高亮不动作，未知不渲染为耗尽。备号旧读数明确“上次/未知”，不承诺够用；经验证的目标新鲜 0% 保留待接棒，实际启动前重验。
- 前台菜单必须由原分屏控制器拥有：默认当前行，`↑/↓` 只变焦点，`Esc` 关菜单、`Enter` 当前行无意图、另一行才对本分屏当前源棒/指定目标写意图。打开、移动/取消不改变登录。菜单状态不抢占非相关按键；退出菜单焦点交回 AGY，`Shift+Tab` 保持原生审批。降级路径的普通 `/exit` 只是退出，不确认目标；仅本次明确启用降级、源任务和账号可归属且原分屏控制权有效时，安全退出后才展示菜单。未启用、`Esc` 或当前项均直接结束，不建意图、不读取/冻结包、不登录。

### 5.2 迁移表（意图状态与启动结果分离）

| 当前 → 后继 | 触发与前置条件 | 异常落点 / 并发与重入 |
|---|---|---|
| 无意图 → `await_exit` / `preparing_packet` | 另一账号 `Enter`，原分屏仍持有已归属源棒；前台确认后等正常退出。降级须已明确启用且退出已证实，才显示菜单供确认；普通 `/exit` 不迁移 | CAS 检查当前棒、实例和账户；同源/目标重复确认复用；已有异目标须先取消且不能绕过未决启动。 |
| `await_exit` → `preparing_packet` | 当前轮停止，提示用户在原窗 `/exit`，源所有者确认正常结束和对应进程真正退出 | 不因 idle、无 PID/权限错误/超时/非正常退出直接放行。保持等待或待人工核证；其他附着同一对话的源进程仍是冲突。 |
| `preparing_packet` → `packet_ready` 或 `blocked/no_evidence` | 读合法落盘证据，冻结校验后的包并提交只读引用 | 有部分证据可冻结 `partial`，无输入保留原因且无可用包。文件/DB 不一致时先核对；仅在确认未取得启动权且原证据仍可用时显式重建包。 |
| `packet_ready` → `await_login` → `await_verification` | 持共享登录域互斥且无受影响会话后，引导官方登录；引导完成/安全退出后发新 challenge | 扫描失败、共享冲突或槽位改绑均阻断并解释；取消/进程中断不回滚官方登录。旧 guide/旧探针结果不能直接授权；原分屏控制权丢失则停在 `blocked/original_terminal_unverified`。 |
| `await_verification` → `ready` / `blocked` | 挑战后的非缓存认证命中目标槽位版本、目标会话认证上下文可绑定；检查账号冲突及 5h | 错号、无来源/epoch、过期留包待核验；新鲜 0% 留包暂停；未知量提示“不保证可用”，但不等同 0%，身份仍须硬校验。 |
| `ready` → `prepared` → `spawn_armed` | 用户已显式确认/重试且拥有可证明的原分屏控制权；核对包、冲突和新鲜目标身份，持久化本次单次启动授权 `spawn_armed`，仅原分屏控制者可在授权仍有效时调用 `agy -i` | `prepared` 阶段没有启动权；可在撤销/确认旧执行者不可能启动后重新核验。`spawn_armed` 已跨持久化安全边界；旧执行者退出或 lease 释放不证明未调用。 |
| `spawn_armed` → `await_new_id` / `uncertain` | 收到子进程标识可记录观察，不能提交棒；已验证的确定“未调用/未创建”结果独立标 `failed_before_spawn` | 超时、不能取 PID、启动后秒退、回调/落盘失败不等于未启动。`uncertain` 不得重新启动；收集专属新会话证据或人工核查。 |
| `await_new_id` / `uncertain` → `consumed` | 本次已启动 attempt 产生、可验证归属的新 ID：绑定启动实例、原分屏和启动时的实际目标身份，不是任何既有 ID。首报可迟到，认证 TTL 过后仍能历史补登记；同一事务认领 ID、写下一棒、推进指针、源棒 `handed_off`、消费意图并记事件 | 历史证据重放只用于登记，不授权启动。已提交重复帧返回同一棒；旧 ID/另一任务的 ID/不同 ID 冲突则待核对，不走普通新任务路径。 |
| `consumed`：`delivery_unverified` → `delivered` / `delivery_needs_review` | 用本次新 ID 关联的实际包读取证据判定；身份、真实新 ID 与阅读是三个独立证据 | 没有实读证据，HUD 不宣称“已接棒”交付成功；允许已确认会话的人工作业，不为同一意图重开对话。 |
| 未消费 → `cancelled` 或 `cancel_requested` | 启动边界前可撤销授权并终止本地动作，保留查询/包；已可能启动时只记取消请求并禁止再启 | 已跨边界仍保存待核验 attempt；若取得合格 ID，要登记已实际创建的棒并标取消请求/交付待核对，不能假装没启动。取消不杀进程、不回滚官方登录。 |

**并发规则**：写 SQLite 只做校验/CAS 与原子数据变更，不在事务内等 TUI、进程、浏览器或大 IO。平台登录域锁覆盖最终冲突扫描、人工登录、重新扫描、目标认证与安全交付启动边界，作用域按已验证共享域而非 DB/cwd；不得持锁等整轮下一棒结束。对同一共享域的旧人工 `start/switch` 同样参与锁。非托管无法同步，证据不足阻断；分屏/账户不等于隔离。状态 `blocked` 携带 `blocked_phase`/原因（例如 `shared_session`、`quota_zero`、`auth_expired`），仅从该安全检查点显式重试，不由 HUD 重绘或平常 `agy` 驱动。

### 5.3 崩溃检查点与重试判据

1. **原分屏控制权可证明**：由原控制者在同窗提供明确的“重试”操作（不要求再敲 `agy-pool`）。先核对 attempt 状态及原分屏的独占控制权；已可能启动则只对账，不开第二棒。仅在证明尚未启动并且旧执行者失去启动权时继续；检查包，重扫共享冲突、重发 challenge、重新绑定目标身份和授权，再走单次启动。结果可观察：同窗显示阻断/校验/重试，其他分屏的 `list/status` 只显示记录。
2. **原分屏关闭，重开后不能证明控制权连续**：记录 `original_terminal_unverified`、保留意图和包可查；另一个 pane、相同 cwd/账号、甚至复用的 pane ID 不视为原控制者。不得自动认领、重新授权或用 `list/status` 恢复。已有合格历史事件仍可由控制器的显式对账处理，仅补登记，不开新会话。跨窗重新绑定不在默认能力内，需另立产品决策和验收。

| 中断位置 | 持久化见证与恢复处理 |
|---|---|
| 包未落盘 / 写临时文件 | 只有 `preparing_packet`，没有发布引用。确认没有启动授权后按同一意图重新构造；清理限本池临时文件。不得用空包放行。 |
| 包已原子发布、DB 尚未写入 | 事务前写同目录临时文件、flush/fsync、原子发布并按平台验证目录持久化；未被 DB 引用的文件是孤儿，不能扫目录认领或传入 `-i`。安全重做时生成新不可变引用；清理不删任何未决 attempt 相关包。 |
| DB 已引用包、登录校验期间 | 重新打开前验证路径、大小、摘要，缺失/不符即阻断；官方登录结果不回滚、不沿用旧 `ready`；仅原分屏控制权仍可证明且收到显式重试时，重查冲突、重发 challenge。包仅在未获得启动权时允许显式重建并保留审计。 |
| `prepared` / `spawn_armed` 与实际调用之间 | `prepared` 无启动权，撤销并隔离旧控制器后可显式重试；`spawn_armed` 后如果没留下权威“未创建”结果，崩溃前后不可区分，进入 `uncertain`。重获锁、PID 缺失或杀掉父进程都不提供未启动证明。 |
| 已调用 / 新 ID 未写入 | 用专属 `attempt_id` 的生产方帧、可校验的启动记录和原生对话记录核对；不靠 cwd、文件时间或扫描最近会话猜测。没有合格 ID 不写下一棒，不重开。即使子进程已退，若有可信持久的新对话证据也可补登记为已结束。 |
| 合格 ID 已持久、登记事务中断 | 保留关键事件至 commit+ACK。合格的 attempt 历史事件即使认证已过期也可由控制器对账并重放登记；唯一键/CAS 落在同一任务同一棒。`list/status` 只查结果；不重验成启动授权、不再拉起。 |
| 已登记、读取包证据不足 | 继续查询/核查该对话，状态“已开新对话，交接待核对”；同一意图已消费。不会用另一普通会话重发，不用阅读失败作为重开依据。 |

### 5.4 交接包生成

- **何时**：仅 M4 源账号已归属、同窗明确确认且源轮/进程正常退出后，才为该意图读取交接来源并冻结包；原 `handoff` 人工预览不等于冻结、确认或领取，不用于绕过 M4 未归属的门禁。包绑定意图与源棒；不依赖源号仍能回答、无额外模型或网络调用。目标新对话的模型/读文件能力是交付本身的一部分，不用于本地生成。
- **内容**：L1＝原锚点/经脱敏、限额的用户目标摘录 + `task.md` 和工作区状态；未明确的验收/约束标“待核对”，不是自造事实。手工锚点仍 ≤600 Tokens、已合法保存的锚点全文不裁；自动锚点只保存有意义的限额摘录，不能摘即声明缺失，绝不充当标题。L2＝最近已完整落盘的有效轮及最新报错，优先已确认的进度。工具“计划调用”与“已写/测试通过”分开，只有可靠的成功结果/Git 可核对事实才陈述，Git 工作区差异不归因给某个分屏。L3＝上一棒、对话与链路的安全溯源，禁止盲重放旧命令/工具调用。
- **质量**：对账日志完整性（已提交步骤、完整 JSON 行、可靠结束边界）、目标/任务文件/Git 可用性。无法证明末轮完整时标“部分交接/待核对”、列证据来源与缺口；若源全部不可用，暂停并给出恢复日志/核对锚点等下一步，不用空白模板或占位符充数。读取做总量/单行限制和范围校验，坏尾跳过但不隐藏缺口。
- **预算及交付安全**：遵循旧三层裁剪优先级，最终对已脱敏成品硬查 `estimated_tokens ≤ 3500`，不单靠旧生成器内部分配。降级裁剪不吞掉来源/未完成提示。`-i` 引导为单行 ≤250 字、仅引用固定验证过的包路径，数组传参不走 shell；先读包、核对目标进度再继续，不自动同意工具审批。包通常以当前用户权限可读；路径不向普通新会话传递，不把路径难猜或同用户文件权限当作账号隔离。已经实际读过的证据必须可关联本次会话与该文件，不能只看模型声称读过。

**Otty 可行性证据（S06，非 AC-03）**：单分屏、真实 `agy 1.5.18`、透明 PTY。AGY 请求 CSI-u flag `5` 并查询；Otty 回 `ESC[?5u`，代理原样写入子进程 PTY，不据此推断 AGY 内部状态。实际按键：普通 `y` 为 `79`（正常输入后清除）；`⌘⇧Y` 为 `ESC[121:89;10u`；`Shift+Tab` 为 `ESC[9;2u`（AGY 从 Auto 切到 Plan）。短文本粘贴和清除有响应；正常 `/exit` 后子进程状态为 `0`，探针记录 TTY 恢复。未人为制造字节分片，未测拦键、菜单、双分屏联调或切号。原始采集在本地留存，不随仓库发布；详见 [测试清单 S06](agy-pool-M4-测试用例.md#1-已做过的能力探针不计正式验收)。

**选型影响**：Otty 保留前台 `⌘⇧Y`，每分屏的 PTY 代理是有证据支撑的候选，不因此宣布唯一方案或前台验收通过。若选该方案，应支持 CSI-u 的备用键码子字段（不能只匹配之前 flag `1` 实测的 `ESC[121;10u`），原样透传查询回复、非目标键和粘贴，不凭传统模式中的普通 `y` 触发。仅在可验证归属当前分屏且能可靠区分按键时展示快捷键；分片、菜单拦截、焦点隔离和恢复纳入完工后验收。Windows 仍独立判断。

**两条正式时序（FR-04/05/09，AC-03/04）**：

1. **前台键已验证**：托管且当前源归属确认时显示 `切换账号 (⌘⇧Y)` / `切换账号 (Ctrl+Shift+Y)`；同窗菜单先确认目标，若忙等本轮停止，提示在原 `agy` 执行 `/exit`，等安全退出后按状态机继续。用户不需另敲 `agy-pool` 或复制上下文。
2. **前台键不可用/冲突**：不安装抢键监听、不显示失效键。仅在本次已明确启用退出后降级、原分屏仍拥有可归属的已托管源任务（账号已核验）时，提示「退出当前会话后选择账号」。原窗正常 `/exit` 只是退出；满足上述条件，同窗控制器才显示方向键菜单。`Esc` 或当前项直接结束，不写意图、不读取/冻结包、不登录；只有选中另一项并按 `Enter` 才确认。本次未明确启用时，普通退出不弹菜单；坏/缺 HUD、缺 ID 或源账号未归属均无操作入口。如何在不抢键、不要求额外 `agy-pool` 命令、也不打扰普通退出的前提下明确启用降级，待两平台探针/产品评审；能力不可用时不假装可选。两端分别记录“前台通过/未通过”和“退出后菜单通过/未通过”，后者不等于前者。

**HUD 展示（FR-02/03/04、AC-07）**：Otty R4 模型冰蓝 `#EBF3FA` 不改；任务 `#F4E0E9` / `#0F172A`、常规字重，账号 `#EFEBF6` / `#554176`，账号换名称不换色；三个独立胶囊，不加括号、连接符、重复标题、任务 ID 或棒次。宽度按显示列计算（CJK/组合字符/ANSI），先截任务名，必要时快捷键独立行，账号和快捷键优先保留；无 Nerd Font 可用 ANSI 矩形回退。配额双池保持 Gemini/3P 高亮及非活跃无底纹；不把“建议换号”与 M4 低额提醒重复渲染。Windows 复用协议和操作文案，不覆写 Windows 现有外观。

**旧人工入口**：保留 `init`、`account add --from-current` / `list` / `remove`、`start`、`anchor edit`、`handoff [--transcript]`、`switch --to/--cancel`、`close` 与查询语法。旧 `start` 仍明确人工建任务；旧按 cwd 省略 TID 的能力不用于 M4 自动配对，涉及 M4 意图的人工排障要求明确 TID 与操作，不能在另一分屏启动/领取。原手工 `switch` 参数可识别；共享认证域内仍有任何可能受影响的会话时，前台、降级、人工入口都硬挡，`--force` 即使二次确认也不解除；仅有客观无影响证据时再评估独立旧路径。手工取消只改变本地状态，不回滚官方登录；旧诊断继续不得杀源会话、不打印包正文/凭据。

## 9. 实现接口与一致性约定

以下名称为评审中的**逻辑接口**，不要求拆成同名文件或引入新进程。继续沿用标准库、现有跨平台 Runtime 与 SQLite；涉及官方能力的条件不会因接口存在而视为已实现。

### 9.1 职责到模块

| 组件 | 输入与输出 | 实现边界 |
|---|---|---|
| Pool 托管入口 / 分屏控制器 | 原生 argv、当前端点、受信 HUD 握手 → 本次控制器、启动实例、子进程句柄 | 一次启动一个控制器；解析原生二进制避免递归。只等待自己启动的 child，不能按任务名、cwd、账号或终端列表反查“最近退出”。普通退出收尾而不发起换号；客户端不支持时按 §6 降级。 |
| Pool `runtime.py` / `runtime_macos.py` 与平台适配层 | 终端能力、原生退出信号、流程独占、官方账号校验结果 → 规范化能力和证据 | 仅 Runtime 能报告实际 child、退出与 PTY 能力，不替业务自动选择任务。macOS Otty 前台候选为单分屏 PTY；Windows 的旁路/ConPTY 仍待探明，不继承 macOS 结论。 |
| Pool 状态控制与 `store.py` | 事件、明确用户动作、当前记录 → CAS 事务、只读投影、可追溯的阻断原因 | 唯一键、领包、变更审计和下一棒推进归 Pool。持久化不得存凭据或对话原文。`list/status` 只投影结果，不调用运行时恢复。 |
| Pool `handoff.py` | 已退出、已明确确认的源棒与受限本地证据 → 不可变包引用、质量和摘要 | 字节、限额、脱敏和 L1/L2/L3 在生成时确定，发前再核对。无内容或校验失败只返回阻断，不自行找其他会话的包。 |
| HUD 两分支 | 原生帧/已验证日志来源 → 版本化事实；Pool 视图 → HUD 渲染 | 采集、渲染，不掌握任务、换号、交付的写权限。只在各自分支接入共用 v1 协议；Otty 专属 R4 不合入 Windows 分支。 |

### 9.2 控制权、按键和退出

- **一个控制器拥有一个活的本地前台端点**：记录控制器实例随机标识、`launch_id`、被该控制器启动的 child 句柄及 PID/创建时间；pane/TTY 只辅助验证当前终端，不当任务主键或重入凭证。收到真实首问与 ID 后把该实例和首棒关联；恢复旧对话时只允许在没有其他有效所有者且独占性可验证时产生新附着，不更改旧棒的创建实例。打开菜单先检查此绑定，确认时再次核对源棒与当前控制权。
- **输入切换**：没有菜单时，只有分屏代理读取本地输入，原生 AGY 从其 PTY 接收；按已协商的协议识别完整事件而非按一次 `read()` 的边界识别。正常字符、`Shift+Tab`、查询响应和粘贴原样给 AGY；不解析粘贴正文里的“疑似快捷键”。只有完整、无歧义的目标组合键可被消费。状态不明、截断、缓冲上界超出及协议未协商时停止拦截，保留原生输入，不对残片判键。
- **菜单与恢复**：仅同窗控制器临时处理菜单导航并保留原生执行，渲染不遮全屏；退出菜单恢复焦点和正常转发，窗口尺寸变化继续传到原生进程。正常退出、错误和中断路径恢复终端状态；不能安全恢复/无法区分按键时，关闭该前台能力并给出可读原因。无已证实的显式降级入口时，普通 `/exit` 仍只退出，不弹菜单。
- **原控制器仍活着才有首版同窗重试路径**：可以验证自己绑定的 child 正常 `/exit`，随后在原端点显示明确重试动作。控制器崩溃时即使 pane 还在，也不自动视作控制权连续；当前设计只保留待接棒状态和历史对账，不承诺能重新启动。本限制若无法满足产品重试期望，回评审决定是否增加独立控制权见证，不能用相同 pane ID、PID、目录或口头确认补证。`prepared` 记录可在证明旧授权失效后重验；`spawn_armed` 后仅有可靠的「尚未调用」或平台明确返回「未创建任何进程」可作为重试前提。未见证、调用结果丢失或子进程不在，均进入待核对。

### 9.3 版本化事件与只读视图契约

§3.2 是合成样例；下表给出设计语义。字段可在帧内，亦可来自与该帧绑定的持久接收记录，不能从不同启动实例拼接。事件来源标识须由各平台的能力证据校验通过，不能相信帧中自称的账号、时间或生产者。

| 类型 | 作用域 / 最小证据 | 消费与拒绝条件 |
|---|---|---|
| 公共头 | `v`、`event`、`producer_instance_id`、`seq`，以及已分配的 `launch_id` 或 `probe_id` | 生产者重启获得新实例 ID，序号在实例内单调；`(scope,producer_instance_id,seq)` 做投递幂等键，同键异载荷隔离。未知版本/范围、损坏事件不推进状态。 |
| `conversation_evidence` | 普通或已绑定启动；`native_namespace`、真实 ID、`kind`、原生 `source` 与 `source_ref`，标题类携带净化后的名称，首问类为已提交证据引用 | 任务唯一性按规范化对话键，不按投递顺序；晚到首问/标题可以匹配同一真实 ID，只有 #1 原生标题可回填。不存首问原文。 |
| `session_identity` | 普通或已登记棒；真实 ID、上游身份摘要、原生来源及观测时刻 | 只用于本棒身份补归属/操作资格，不能代替重登探针。已归属不代表永远有启动权限。 |
| `quota_sample` | 槽位登记版本与身份关联、上游采样时刻、独立配额桶、未四舍五入的比例；可信窗口证据可缺 | 槽位、身份、配额桶和真实采样同源；采样缺口不由重绘填补，无可信窗口不发一次性提醒。 |
| `auth_observation` | 单独挑战作用域；本次探针、challenge、身份摘要、实际观测时刻、官方认证上下文的非敏感引用及来源 | 身份一致且新鲜才进入授权判断；原始探针短留存。不能复用旧共享快照或普通 `session_identity`，也不保存认证材料。 |
| `new_conversation` / `packet_read` | 仅本次已启动 attempt；真实新 ID/命名域、原生生成证据与当时目标身份。实读另带匹配包摘要、成功的原生读取事件引用 | `new_conversation` 只提交下一棒；`packet_read` 只确认已读，不从模型复述、工具计划或文件时间推断。迟到/重放仍需与原 attempt 的持久见证相符，且不能重新授权启动。 |

**提交语义**：关键事件由受控通道原子发布，Pool 核对后在同一 SQLite 事务记录幂等键、最小可追溯证据和领域变更；仅在提交后确认接收。提交后 ACK 前崩溃允许重投，已落账的事件返回原结论，投递去重不能替代任务/意图唯一约束。历史对账依赖运行当时留下的绑定见证，不靠原 PID 仍活着；随意复制 JSON 不视为可核验重放。授权材料过期即可清除，已授权 attempt 的最小审计引用保留到对账结束，留存时长待评审。临时邮箱不作为第二任务库。

**显示投影**：HUD 只拿当前 `launch_id`、真实对话 ID、任务显示名、归属账号/未知、当前能力及状态文案；不发完整正文、凭据、包路径或可当授权使用的引用。不匹配当前启动实例、坏帧或无法证明有效能力时忽略投影，不渲染可操作入口。CLI 查询只显示持久结果；建议按以下原因码区分恢复入口，不要求对外固定英文文案：`identity_unverified`、`key_route_unavailable`、`shared_session`、`quota_zero`、`auth_expired`、`consumer_unbound`、`original_terminal_unverified`、`spawn_uncertain`、`delivery_unverified`。

### 9.4 一次性交付授权与跨库屏障

1. **发出 `-i` 之前绑定实际消费者。** 每次授权必须同时关联：源意图/任务/棒次、原分屏控制器、目标槽位登记版本、挑战与新鲜身份观测、实际启动要使用的可验证官方认证上下文、launch/attempt、包摘要。最终执行门检查这些绑定对实际接收 `-i` 的客户端有效，覆盖进程启动到初始指令消费的间隔；只做探针匹配、互斥或重复扫描不达标。没有官方或等价的可验证绑定时，留包并报 `consumer_unbound`，**连包含包路径的 `-i` 都不传**。新 ID 即使随后出现也只可对账，不能弥补事前授权。
2. **进程锁只串行当前执行；跨库屏障处理崩溃。** 建议在实际认证共享域的现有锁目录下增加独立的最小持久标记，置于任何自定义 `pool.db` 及 v1/v2 备份之外。内容只含不敏感的域标识、对应库/意图/attempt 的索引引用与记录阶段，不含包、账号凭据或正文。至少在进入可能改变共享登录的阶段前写入并校验；授予 `spawn_armed` 之前确认同域标记已持久。受管启动、换号、显式恢复、旧人工入口及迁移回退都先检查；不能让仍会改变同域登录的旧程序绕开。标记与 DB 任一断点残留时保守阻断相冲突动作，不通过超时、进程消失或换库清标记。状态查询和完全原生无授权的工作流不读取交接内容；非托管共享域风险继续按 §3.1 的实际消费者绑定解决。
3. **清除和回退**：只有在持同一域锁且核对原意图已安全终止、相应启动已权威证明未创建，或已提交真实下一棒并解除旧授权后，才记录状态并清除该项；身份仍可能改变的官方登录也须先停止或有实际结果。标记异常只允许人工核照，不提供“强制再启”功能。迁移的静止点是旧写者正常退出且所有待处理授权已核对，不能用互斥锁空闲或数据库快照代替；无法让旧链遵守屏障时只做停用／只读归档，不恢复有认证副作用的旧命令。

## 10. 评审结论、可并行项与门槛

| 可行性判断 | 当前可决定 | 进入实现／启用前需闭合 |
|---|---|---|
| 本地状态与交接 | 可以按本方案评审 SQLite 迁移、首问去重、只读查询、按意图领包、脱敏预算和恢复接口。 | 开发前冻结 §9.3 协议与 §9.4 的持久屏障契约。正式夹具及真机功能测试在开发完毕后执行。 |
| Otty 前台键 | S06 足以保留 `⌘⇧Y` 和分屏 PTY 接入候选，无需为了现有证据不足先改键或只做降级。 | 实现后验完整按键/粘贴分片、当前分屏拦截、`Shift+Tab`、异常终端恢复。显式同窗降级触发方式另定。 |
| Windows Terminal | 可以共用 M4 领域规则及只读/日志契约，终端接入单独设计。 | 不把 Otty 的 CSI-u、进程控制或配色结论推给 Windows；待明确按键路由、正常退出和同窗降级。 |
| 原生证据 | 首问、标题、5h 窗口、官方身份和包实读已经定义需要的信号；这些是接口要求，不是已知上游承诺。 | 真机证据缺失时，分别停在不登记／`todo`／不发一次性提醒／不交付／交付待核；不借用户数据、首问截取或重绘兜底。 |
| 正式发布 | 保持 PRD 原验收，不默认单平台或降级发布。 | 各平台 AC-01～07 独立签收。涉及真实首问/登录、切号或共享域的实验需相应环境和单独授权；不能证明实际消费目标身份是自动接棒的硬阻断。 |

**评审建议**：先评审接口和安全边界，然后才定实施顺序。平台能力未闭合时，可以推进与平台无关的本地实现设计，不启用真实切号／交付；不把技术可行性探针当功能验收。若待验证能力改变产品体验（例如只能退出后选账号、失去原控制器时不能重新启动、仅单平台可达），列入产品范围决策，不在开发中静默变更需求。
