# macOS 适配与验收

这是 `feat/macos` 的增量适配。Windows 的 Win32 后端和启动脚本不变；SQLite、交接包、手动浏览器换号和独立 HUD 校验规则两端共用。不跨设备同步账号、数据库或历史对话。

| 行为 | macOS 预期 |
|---|---|
| 运行入口 | `sh /path/to/agy-pool/agy-pool.sh ...`；需要 `python3.12`，交互命令还需要本机 PATH 上的 `agy`。 |
| 进程冲突 | 只检查当前系统用户的 `agy`；同时比较 PID 和微秒级启动时间。遇到已识别但无法核验身份的进程，仍视为可能冲突。 |
| 换号互斥 | 默认 `~/Library/Application Support/agy-pool/switch.lock`。锁属于系统用户，不属于 SQLite；进程退出后操作系统释放，锁文件留作下次复用。 |
| 前台会话 | 引导、账号校验和正式 `agy` 都使用当前终端。正式会话通过存活检查并写入状态后，换号锁释放，但 CLI 继续等待 `agy` 退出，避免 shell 与 `agy` 争用输入。 |
| 登录数据 | 复用现有 HUD 的状态输出；不读写钥匙串、浏览器凭据或 Google 令牌。校验窗口没有本次登录的新状态时不会接棒。 |

## 自动化

在 Mac 上从仓库目录执行 `python3.12 -m pytest -q -rs`。原生测试使用无登录的进程、伪终端和临时文件；不会触发真实换号。从非 Mac 环境运行时会跳过 Darwin 接口相关测试。

## 真机走查

仅在能安全关闭现有 `agy` 的时间，使用自己授权的账号操作。确认现有 HUD 在 Mac 版 `agy` 中已启用。

1. 用普通 `agy` 登录主账号、等 HUD 刷新后注册 `main`；以相同方式注册 `backup`，再用官方登录流程回到 `main`。
2. 执行 `sh agy-pool.sh start 'Mac 验收' --account main`。当前终端先进入无提示词的校验会话；等 HUD 刷新并 `/exit`，随后应进入正式会话。发送一条可辨识的非敏感测试任务，在另一个终端以 `status T1 --json` 确认棒次为 `running`。
3. 保留源会话，在另一个终端运行 `sh agy-pool.sh switch T1 --to backup --force`：应返回 `6`，不得进入换号。源会话 `/exit` 后，再打开一个普通 `agy`，不加 `--force` 的切号应返回 `3` 并列出该进程。
4. 关闭冲突窗口后执行切号。引导结束后，等待新的验证会话刷新 HUD，再 `/exit`。如果实际登录不符，应返回 `4`；如果拿不到新的状态，应返回 `1`；两种情况都不得启动下一棒，也不得回退使用共享状态。
5. 按官方流程切对账号后验证能进入第二棒，交接包应包含第 2 步的测试任务。若只能生成缺失日志的交接包，记录 HUD 的日志路径布局，用 `--transcript` 单独验证手动指定来源。第二棒 `/exit` 后，`status T1 --json` 应显示 `closed`。
